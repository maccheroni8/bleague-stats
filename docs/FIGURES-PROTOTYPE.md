## 図解タブの構成

- `/figures` の中で「チーム／選手」。年齢分布はチーム側、初期表示もチーム。選手側は準備中。
- 図は固有ID・対象・見出し・説明を持ち、条件と描画と保存対象を専用の部品に分ける。試作は `age` の1つ。
- 図が増えた段階で一覧＋選択中の図という構成にする案。`figure=age` は今回導入済み。図の選択UIは未実装。選手の準備中画面は `entity=player&figure=index`。
- 年齢分布のURLは `#/figures?season=2026-27&entity=team&figure=age&min=15&cls=all&gt=regular&line=mean`。条件の既定値は省略できる。古いURL（対象未指定、または `entity=player` で図の指定なし）も条件を保ったままチームの年齢分布へ置換し、履歴は増やさない。
- 条件は既存のURL状態管理を使い、変更のたびに履歴を増やさない。シーズン変更でも条件を保持。
- データ更新は既存の自動集計・デプロイに追従。ページを開き直した時に最新を読む。開きっぱなしでの定期再取得は未実装。
- 図の表示に必要なデータが無いときは説明を表示。新たな保存列やファイルは作らない。
- リーグはページの `category` 引数で受け取る接点を用意。現状は premier のみ。one を渡すと準備中と表示し、premier の図を誤表示しない。B.ONE のURL・読み込み・順位データへの接続は別途。
- 登録区分の選択肢は `FIGURE_CLASSES` に集約。ただし現行索引は jp/intl の2群なので、選択肢の追加だけでは4区分に分けられない。2026-27以降の選手×シーズンの正確な区分を、Claude Code側の成果物から結合する読み込み口が必要。過去シーズンは3選択肢を維持する。

## 年齢分布の数え方（試作案）

既存の選手試合索引だけをブラウザで読む。各選手×チームについて、選択した試合区分で出場時間が正の試合の出場時間を足し、出場試合数で割る。
DNPは分母に入れず、判定は丸め前の平均値で行う。表示は分:秒。
条件を満たす各所属チームに点を1個ずつ置く。全体平均・中央値は条件を満たした選手IDの重複を除いて計算し、出場時間では重み付けしない。
年齢は既存の `ageForSeason` と `ageBaseDateLabel` を共用。シーズン終了年6/30と今日JSTの早い日付の満年齢。
生年月日が無い選手は図・人数・平均・中央値から除き、除外件数（選手×チーム）を注記。対象0人は人数0・平均と中央値は「—」。
地区・順序は順位表と同じ `pickerTeamOrder`。過去の中地区も表示。ポストシーズンを選んでも並びはレギュラーシーズンの地区順位。
「なし」も出場者のみ。登録だけで未出場の選手は現在の試作には入れない。

IL: 選手マスタ、選手集計、試合索引に指定日時点のIL登録状態・登録解除期間は無い。ルーキー関連の注記はあるが、図のIL除外には利用できない。
そのため「IL登録選手は除外」とは書かず、「IL登録選手は除外していません」を図・画像に残す。IL情報の取得や保存は今回行わない。

## チーム図1: ORtg / DRtg（設計のみ）

横軸ORtgは右ほど良い。縦軸DRtgは**上ほど数値が小さい**反転軸にする。これで右上が「攻守とも良い」。
他の区画は左上「守備が良い・攻撃に課題」、右下「攻撃が良い・守備に課題」、左下「攻守に課題」の仮案。表現は決定待ち。
中央線は対象試合を合わせたリーグ基準（総得点÷総ポゼッション×100）を提案。単純なチーム平均との違いを説明して選ぶ。
チームロゴを点にし、重なりは一覧表・選択時の強調で補う。座標をずらして数値を変えない。ロゴ欠損時はチーム略称。

期間は「シーズン全体／各チームの直近5試合／直近10試合／日付範囲」。試合区分も既存方式。
直近N試合は各チーム別であり、対象日付が異なることを注記。N未満は実際の試合数を明記し、0試合は描かない。
既存の team-games と `sumTeamGameLogs`、全チームスタッツと同じ列の式を利用する案。試合ごとのORtgの単純平均にはしない。
現在の全チームスタッツと同じポゼッション定義を使う場合は画面だけで作成可能。実ポゼッションに統一した新しい値を希望する場合は、Claude Code側の再集計方針に合わせて保留。
新しい近似式は導入しない。式・期間・中央線・区画名を決めてから実装する。

## チーム図2: 他地区と1試合だけの対戦表（設計のみ）

行＝自チーム（地区ごと・順位順）。列＝ホーム1試合／アウェイ1試合。相手ロゴと略称を並べる。
シーズン全体の同一対戦カードを数え、他地区かつ予定を含む総対戦数が1のカードだけ採用。まだ1試合しか消化していないカードとは区別する。

既存の日程画面と同様に、games-summary、schedule の upcomingGames、resultOnlyGames を試合IDで重複除去して結合。中止は別扱い。
開催予定はチームIDが無いがチーム名を当該シーズンのteamsに照合可能。旧名称は当時の名称・履歴で補う。曖昧・未対応の名前は推測で埋めない。
地区は当該シーズンの地区データ、ロゴは既存ファイルを読む。
2026-27の同一の手元データでは終了等116件＋予定654件＝重複除去770件、予定チーム名の未照合0件。ただしこれだけでは「年間全試合が揃っている」とは保証できない。

足りないもの・確定が必要なもの:
- 年間日程が全て収録済みと確認できる根拠。シーズンの予定総試合数・各チームの総試合数との突き合わせが必要。足りない段階は「暫定」とし断定しない。
- 予定の各試合には試合区分が無い。今後ポストシーズン予定が混在する時の切り分けが必要。日付だけで推測しない。
- 中止・不戦勝の扱い。「当初の組み合わせ」を示すなら中止も残す、「実際に戦う」を示すなら除く。表の目的をユーザーが選ぶ。
- 未照合チーム・地区・ロゴの欠損時の扱い。B.ONEは並行作業の成果と接続してから。

以上が揃えば画面側で自動生成できる見込み。今回は表も新規データも作らない。
